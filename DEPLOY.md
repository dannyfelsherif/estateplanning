# Deploying to Render

This repo includes a `render.yaml` Blueprint, so Render can stand up the
whole service without you configuring build/start commands by hand.

## Steps

1. Go to https://dashboard.render.com and sign in (or create a free account).
2. Click **New +** → **Blueprint**.
3. Connect your GitHub account if you haven't, then select the
   `dannyfelsherif/estateplanning` repository.
4. Render reads `render.yaml` and shows one service:
   `ai-estate-planning-agent`. Click into it before deploying and fill in
   the environment variables marked "sync: false" (Render will prompt for
   these):
   - `ANTHROPIC_API_KEY` — your real Anthropic API key.
   - `ADMIN_EMAIL` — the email for the first attorney login.
   - `ADMIN_PASSWORD` — a strong password (change it after first login;
     there's no in-app password-change screen yet, so for now redeploy
     with a new value to rotate it).
   - `SESSION_SECRET_KEY` is auto-generated by Render — no action needed.
5. Click **Apply** / **Create Blueprint**. Render will build and deploy;
   the first build takes a few minutes.
6. Once live, Render gives you a URL like
   `https://ai-estate-planning-agent.onrender.com`. Log in with the
   `ADMIN_EMAIL` / `ADMIN_PASSWORD` you set.

## Important: free-tier data persistence

The `free` plan in `render.yaml` has **no persistent disk** — the SQLite
database and any uploaded documents live on the container's local disk and
are wiped whenever the service redeploys or spins down from inactivity
(free instances sleep after 15 minutes idle and wipe local state on the
next wake). That's fine for demoing the workflow, but **do not use the
free tier for real client data**.

To persist data across restarts:

1. Upgrade the service to at least the **Starter** plan in the Render
   dashboard (Settings → change plan).
2. Add a persistent disk (Settings → Disks → Add Disk), mounted at
   `/var/data`, sized to your needs.
3. Update the service's environment variables:
   - `DATABASE_URL=sqlite:////var/data/estate.db`
   - `UPLOAD_DIR=/var/data/uploads`
4. Redeploy.

For anything beyond a demo/pilot, also see
[`docs/SECURITY_CHECKLIST.md`](docs/SECURITY_CHECKLIST.md) — encryption at
rest, TLS (Render provides this by default on its own domains), and a data
retention policy should all be confirmed before real client PII goes in.
